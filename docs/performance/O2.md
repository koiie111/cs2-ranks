Source baseline: `095e7047168d135be2fd97319a08c5e44699f567` (`main`).
Candidate branch: `codex/perf-ranks-fakerank`.

## Change

The former 64 Hz loop read every player's rank and wrote three native fields every tick. Two empty-server builds that moved the native writes to 4 Hz failed client acceptance: Fake Rank disappeared. The revised candidate preserves the baseline's three native writes and held-TAB reveal on every tick. It caches the Core XP/rank lookup and rank calculation at 4 Hz, refreshing immediately on TAB press, and replaces string button detection with `PlayerButtons.Scoreboard`. `PlayerExperienceChanged` is deliberately not subscribed: Core calls it before changing XP, and its return value can alter XP awards.

The configured rank mapping, XP ceiling, command name, permissions, and native reveal message are unchanged. The connection cache is cleared on disconnect, map start, config reload and plugin unload. Late Core API readiness is retried by the reconciliation timer.

## Follow-up: limit native writes to active TAB viewers

Review against the O2 plan found that the accepted candidate still wrote wins/type/rank for every player on every tick, even with no scoreboard viewer. The follow-up writes those fields when the cached rank changes, on a new connection or spawn, and for all eligible players on each tick while at least one player holds TAB. A 0.25-second reconciliation also writes them while TAB is closed, to keep the client rank data warm. It retains the previously accepted per-tick write/reveal behavior during TAB, including late joiners. `RankChanged` updates immediately after Core changes the rank; the reconciliation also catches direct give/take/set XP operations that do not raise that event. The plugin unsubscribes from Core on unload. `PlayerExperienceChanged` remains unsubscribed because Core invokes it before applying XP and uses its return value to change the award.
