## Change

The former 64 Hz loop read every player's rank and wrote three native fields every tick. The candidate reconciles at 4 Hz, writes only when the value or connection changes (or when a native field was reset), and refreshes all values immediately before a scoreboard reveal. It uses the CSS scoreboard button flag and `OnPlayerButtonsChanged` rather than string conversion. A narrow tick listener retains the reveal message while TAB is held; the first client test found that an edge-only reveal hid Fake Rank. `PlayerExperienceChanged` is deliberately not subscribed: Core calls it before changing XP, and its return value can alter XP awards.

The configured rank mapping, XP ceiling, command name, permissions, and native reveal message are unchanged. The connection cache is cleared on disconnect, map start, config reload and plugin unload. Late Core API readiness is retried by the reconciliation timer.
